#+title: milestone 1: a minimal asahi image
#+date: 2026-07-25
#+options: toc:2

* objective

publish a rebaseable arm64 image that changes as little as possible while
proving the complete build, signing, ghcr publication, and rebase path.

the acceptance criteria are:

1. the image derives from fedora asahi remix atomic silverblue 44;
2. github actions builds it natively on arm64;
3. tailscale is installed and =tailscaled.service= is enabled;
4. homebrew initializes on first boot;
5. firefox and chromium are installed as native fedora rpms;
6. =update-m1n1= works with rpm-ostree's canonical file timestamps;
7. the image is signed and published to the owner's ghcr namespace.

* why this base

an ordinary fedora or universal blue image does not contain the apple silicon
kernel and platform integration needed by the machine. the selected image is:

#+begin_example
quay.io/fedora-asahi-remix-atomic-desktops/silverblue:44
#+end_example

pinning =44= prevents an unattended major fedora transition. scheduled builds
still receive new fedora 44 images from upstream.

the upstream project is explicitly unofficial and experimental:

- https://github.com/fedora-asahi-remix-atomic-desktops/images
- https://github.com/fedora-asahi-remix-atomic-desktops/images/issues/5

* recipe

the complete behavior is declared in =recipes/recipe.yml=. in outline:

#+begin_src yaml
base-image: quay.io/fedora-asahi-remix-atomic-desktops/silverblue
image-version: 44
platforms:
  - linux/arm64
#+end_src

tailscale comes from its official fedora repository. the checked-in repo file
limits that source to the =tailscale= package, and bluebuild removes the repo
configuration after the build:

#+begin_src yaml
- type: dnf
  repos:
    cleanup: true
    files:
      - tailscale.repo
  install:
    packages:
      - repo: tailscale-stable
        packages:
          - tailscale
#+end_src

firefox, its language packs, and chromium resolve only from the inherited
fedora repositories. no browser flatpaks are configured:

#+begin_src yaml
install:
  packages:
    - firefox
    - firefox-langpacks
    - chromium
#+end_src

homebrew uses bluebuild's runtime-aware module rather than copying a mutable
brew installation into the immutable image:

#+begin_src yaml
- type: brew
  brew-analytics: false
#+end_src

the daemon is enabled declaratively:

#+begin_src yaml
- type: systemd
  system:
    enabled:
      - tailscaled.service
#+end_src

* atomic m1n1 compatibility

rpm-ostree canonicalizes package files in =/usr= to an epoch-zero timestamp.
the fedora =update-m1n1= script runs =gzip -c= over u-boot while using
=set -e=. gzip warns that the timestamp cannot be represented, exits with
status 2, and therefore leaves =boot.bin= unchanged.

=files/scripts/patch-update-m1n1.sh= makes the smallest semantic correction:

#+begin_src diff
-gzip -c "$U_BOOT" >>"${TARGET}.new"
+gzip -nc "$U_BOOT" >>"${TARGET}.new"
#+end_src

=-n= tells gzip not to encode the input filename or timestamp. the build-time
patch requires exactly one copy of the known upstream line; it fails closed if
upstream changes, preventing a stale or misapplied workaround from shipping.

the failure and correction can be reproduced without writing the esp:

#+begin_src sh
input=/usr/share/uboot/apple_m1/u-boot-nodtb.bin
stat -c 'epoch=%Y' "$input"

gzip -c "$input" >/dev/null
echo "$?"

original=$(sha256sum "$input" | cut -d' ' -f1)
roundtrip=$(gzip -nc "$input" | gzip -dc | sha256sum | cut -d' ' -f1)
test "$original" = "$roundtrip"
#+end_src

on the first published image, =stat= returned epoch =0= and ordinary gzip
printed =warning: file timestamp out of range for gzip format= before exiting
=2=. the original and =-n= round-trip hashes both were
=0de50ffa28010b67405d84312b5699e76497fe573de260cfd734383437358956=.
two independent compressed runs also produced the same sha256,
=6a079b34e5dce85d086cdda1e426de07f0081cde2d673ef1f6e28b2886fd548f=.

* build path

the workflow uses github's native arm64 runner. this matters: the asahi base is
arm64-only, and emulating the image on an x86 runner adds time and another
failure surface.

the workshop-created =SIGNING_SECRET= and checked-in =cosign.pub= are retained.
bluebuild publishes the signed result to:

#+begin_example
ghcr.io/okwalerie/asahi-bluefin:latest
#+end_example

* reproducible preflight

validate yaml syntax:

#+begin_src sh
yq eval '.' recipes/recipe.yml >/dev/null
yq eval '.' .github/workflows/build.yml >/dev/null
#+end_src

validate the recipe with the same bluebuild cli family used by the action:

#+begin_src sh
podman run --rm \
  --volume "$PWD:/repo:Z" \
  --workdir /repo \
  ghcr.io/blue-build/cli:latest \
  bluebuild validate recipes/recipe.yml
#+end_src

confirm the selected upstream image is arm64 and bootable:

#+begin_src sh
skopeo inspect \
  --no-creds \
  docker://quay.io/fedora-asahi-remix-atomic-desktops/silverblue:44 \
  | jq '{Architecture, Digest, Labels}'
#+end_src

* post-publish verification

verify the registry signature before rebasing:

#+begin_src sh
cosign verify \
  --key cosign.pub \
  ghcr.io/okwalerie/asahi-bluefin:latest
#+end_src

after rebase and reboot, collect the following evidence:

#+begin_src sh
bootc status
systemctl is-enabled tailscaled.service
tailscale version
/home/linuxbrew/.linuxbrew/bin/brew --version
rpm -q firefox chromium
#+end_src

expected results are a booted =ghcr.io/okwalerie/asahi-bluefin= image, an
enabled tailscale daemon, and successful version output from both installed
tools.

* deliberately deferred

this milestone does not add codecs, desktop applications, personal rpm repos,
automatic operating-system updates, or automatic =m1n1= refreshes. the manual
refresh is made functional, but scheduling and coordinating it with deployments
remain deferred.

successfully on the target m1 pro. the live deployment used unmodified
=update-m1n1-20250713-7.fc44= and =uboot-images-armv8-2026.04-102.fc44=
package contents; rpm-ostree had canonicalized their timestamps.
