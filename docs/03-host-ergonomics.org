#+title: milestone 3: declarative host ergonomics
#+date: 2026-07-25
#+options: toc:3

* objective

promote the useful, boot-tested host settings into the image without importing
machine-generated deployment arguments or using universal blue kernel modules
against the asahi kernel.

the source host was inspected read-only before writing this configuration.

* exact host state

the live kernel arguments contained deployment-generated root and ostree values
plus two portable preferences:

#+begin_example
appledrm.show_notch=true
hid_apple.swap_fn_leftctrl=1
#+end_example

only those two arguments are declared through bluebuild's =kargs= module. root
uuids, subvolumes, and ostree deployment checksums must remain generated by the
deployment machinery.

the live =localectl= state was:

#+begin_example
vc keymap: us-colemak
x11 layout: us
x11 model: microsoftpro
x11 variant: colemak
x11 options: terminate:ctrl_alt_bksp
#+end_example

the exact =vconsole.conf= and xorg fallback configuration are copied as image
defaults. =vconsole.conf= is required during early boot, so the =initramfs=
module runs near the end of the recipe after the file is present.

the gnome user had these input settings:

#+begin_src scheme
sources=[('xkb', 'us+colemak')]
xkb-options=['altwin:swap_alt_win']
#+end_src

they are encoded as strictly compiled gschema defaults. gschema defaults do not
replace an existing user's explicit dconf values, which is the desired
precedence rule.

* extension policy

fedora 44 supplies signed, architecture-independent packages for appindicator,
blur my shell, caffeine, dash to dock, gsconnect, and just perfection. the image
layers those packages instead of downloading extension zips during each build.

the extensions are not force-enabled. extension enablement is mutable gnome
user state and remains controlled through extension manager. the audited user
currently has an explicit empty enabled-extension list, so a system default
would not override it anyway.

* fonts

the host had no nerd font family. the image installs jetbrains mono nerd font
and the symbols-only family from the fixed nerd fonts =v3.4.0= release urls:

- https://github.com/ryanoasis/nerd-fonts/releases/tag/v3.4.0

using fixed urls avoids the fonts module's normal unpinned =latest= lookup. the
upstream archives still do not carry a checksum in the bluebuild recipe schema,
so this is pinned-by-version rather than fully content-addressed.

* chezmoi, justfiles, and soar

chezmoi =2.70.5= is available as a fedora 44 aarch64 package and is installed
through dnf before bluebuild's chezmoi module runs. the module sees the existing
=/usr/bin/chezmoi= and therefore skips its otherwise amd64-only downloader. its
useful user services are enabled for all users with:

#+begin_example
repository: git@github.com:okwalerie/dotfiles.git
branch: fedora-asahi-arm64
run-every: 1d
file-conflict-policy: skip
#+end_example

the repository is private. first-login initialization therefore requires the
user's github ssh authentication to work in that session. no deploy key or
credential is embedded in the image. =skip= preserves locally modified files
instead of allowing an unattended timer to overwrite them.

the justfiles module provides four real =blujust= recipes:

- =blujust status= shows bootc and updater/m1n1 state;
- =blujust update= runs uupd without forcing a reboot;
- =blujust enable-cowork= grants the current user kvm group membership;
- =blujust verify= inventories image packages and flatpaks.

soar is installed as a reversible experiment, with its automatic upgrade timer
disabled. it downloads portable applications from its own mutable package
universe, which overlaps conceptually with brew. if it does not demonstrate a
clear advantage, removing it is preferable to maintaining two user package
managers: https://blue-build.org/reference/modules/soar/

* rejected module and kernel ideas

| item | decision | reason |
|-
| =rpm-ostree= module | reject | dnf5 is the current build-time package composer for this bootc fedora 44 image |
| =akmods= module | reject | manages universal blue's prebuilt module ecosystem, not arbitrary asahi 16k-kernel experiments |
| =gnome-extensions= module | reject | fedora packages are signed and less network-fragile; gsconnect is incompatible with its generic zip path |
| =os-release= module | reject | cosmetic identity changes can break fedora/copr detection |
| =yafti= | reject | deprecated first-boot ui with no role in a fixed personal image |
| empty =justfiles= | reject | added only after concrete operational recipes existed |

the current asahi support verdicts are:

- usb-c displayport alt mode remains developer-only work in the =fairydust=
  kernel branch, with port, hotplug, display-count, colour, and timing limits;
- the shipped asahi kernel already carries stable suspend support and its
  downstream cpuidle improvement;
- the experimental pmp device-tree option may reduce idle power but is not yet
  validated across machines or enabled by default;
- the apple neural engine driver remains out of tree with no fedora asahi
  package or stable release.

none of these is an appropriate akmod for the weekly main image. usb-c display
or pmp testing would require a separate experimental image and explicit
rollback/serial-console acceptance, not a hidden toggle in this one.

* validation

before publishing:

#+begin_src sh
podman run --rm \
  --volume "$PWD:/repo:Z" \
  --workdir /repo \
  ghcr.io/blue-build/cli:latest \
  bluebuild generate recipes/recipe.yml

just --fmt --check --unstable \
  --justfile files/justfiles/asahi-bluefin.just
#+end_src

after boot:

#+begin_src sh
rpm-ostree kargs
localectl status
gsettings get org.gnome.desktop.input-sources sources
gsettings get org.gnome.desktop.input-sources xkb-options
fc-match 'JetBrainsMono Nerd Font'
blujust status
soar --version
systemctl --user status chezmoi-init.service chezmoi-update.timer
#+end_src
